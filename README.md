## Технологический стек

*   **Язык разработки:** Go 1.26.1
*   **Взаимодействие микросервисов:** gRPC (Protocol Buffers)
*   **Базы данных:** PostgreSQL (с расширением PostGIS для геолокаций), Redis (сессии и кэш платежей), ClickHouse (хранилище аналитики)
*   **Брокер сообщений:** RabbitMQ (асинхронное взаимодействие, Saga-оркестрация, доставка событий в WebSocket)
*   **Интеграции:** ЮKassa (эквайринг, привязка карт), Yandex Cloud Object Storage (S3 для хранения изображений)
*   **Наблюдаемость (Observability):** OpenTelemetry (метрики и трейсы), Jaeger (распределенная трассировка), Prometheus + Grafana (мониторинг), Loki + Promtail (логирование)
*   **CI/CD:** Автоматизация на базе GitHub Actions, Helm, k3s

## Архитектура системы

Проект спроектирован по микросервисной архитектуре и состоит из следующих компонентов:
*   **API Gateway (BFF):** Точка входа для клиентов. Маршрутизирует gRPC-запросы, управляет сессиями, CORS, защитой от CSRF, логированием и WebSocket-соединениями.
*   **Auth Service:** Отвечает за проверку сессий и токенов безопасности.
*   **User Service:** Профили пользователей, геймификация (Wordle "5 букв", "Колесо фортуны", система достижений).
*   **Address Service:** Управление гео-точками доставки на базе PostGIS.
*   **Restaurant Service:** Меню ресторанов, каталоги блюд и рекомендательная система.
*   **Cart Service:** Управление одиночными и групповыми (совместными) корзинами.
*   **Order Service:** Оркестратор заказов (Saga), управляющий оплатой и применением промокодов.
*   **Payment Service:** Интеграция с платежным шлюзом.
*   **Analytics Service:** Накопление бизнес-метрик и отправка аналитических срезов в ClickHouse.

## Инструкция по запуску (How-to-Run)

### 1. Локальный запуск (Local Run)

Этот способ предназначен для проверки работоспособности и локального тестирования бэкенда на вашем компьютере.

#### Предварительные требования
*   Установленный **Docker** и **Docker Compose**
*   **Go 1.26.1** (если планируется запуск без Docker)

#### Быстрый старт через Docker Compose (Рекомендуется)
1.  Создайте локальный файл окружения:
    ```bash
    cp .env.example .env
    ```
    *(При необходимости заполните переменные для интеграции с S3 и ЮKassa в файле `.env`)*

2.  Запустите сборку и старт всей инфраструктуры и сервисов в фоне:
    ```bash
    make d-up
    ```
    *Или напрямую через docker compose:*
    ```bash
    docker compose up -d --build
    ```

3.  Выполните миграции баз данных (включая ClickHouse) и наполните их демонстрационными данными (сидами):
    ```bash
    make migrate-up-all
    ```

После этого бэкенд будет доступен по адресу `http://localhost:8080`, а Swagger — по адресу `http://localhost:8080/swagger/index.html`.

### 2. Развертывание на Production (Deployment)

Деплой всей системы автоматизирован и управляется через GitOps-пайплайны.

#### Архитектура деплоя
*   **Среда выполнения:** Kubernetes-кластер (K3s).
*   **Оркестрация деплоя:** Helm. Каждому микросервису соответствует собственный Helm-релиз, использующий шаблоны из общего чарта `helm/nancats-service` со специфичными значениями из `values-<service>.yaml`.
*   **CI/CD:** GitHub Actions (`.github/workflows/ci-cd.yaml`).

#### Процесс релиза (CI/CD)
Пайплайн запускается автоматически при пуше в ветки `main` и `develop`:

1.  **Этап тестирования (Lint & Test):** Для каждого измененного сервиса запускаются линтеры (`golangci-lint`) и прогоняются юнит-тесты.
2.  **Сборка образов (Build & Push):** Происходит сборка Docker-образов микросервисов, которые затем публикуются в реестр пакетов GitHub Container Registry (`ghcr.io`).
3.  **Доставка (Deploy):** 
    *   Конфигурационные файлы Helm и манифесты инфраструктуры копируются на целевой сервер по SSH.
    *   Скрипт выполняет обновление или установку Helm-релиза.
